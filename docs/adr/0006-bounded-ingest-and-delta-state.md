# ADR 0006：有界原生写入与统一状态增量

状态：核心实现与本机验证完成，2026-09-06。用户已明确允许破坏旧接口并统一迁移仓库内下游。
真实完整交易日容量验收不在短时合成测试结论内，边界见审计续报。

## 契约

- 原始 append 事件不合并，保持表内 offset 顺序和原子批次边界。
- KeyValue 引擎常态输出带序号、操作和版本的状态增量；flush/stop 不再重复输出全量。
  完整状态由显式快照查询提供，不保留“每批全量”的默认兼容模式。
- 初始化消费者必须安装一致快照及其游标，然后应用连续增量；重复增量不重复应用，缺口
  明确失败并要求重建，不能以部分市场状态继续计算。原始事件消费者不能用状态快照补逐笔缺口。
- `Memory` 与 `Wal` 确认边界不弱化。WAL 仅在 manifest 和恢复检查点均安全后回收；
  SHM 在 manifest 覆盖且读者保护允许后退役。
- 精确回执从热内存转磁盘索引，保留有效 producer epoch 内的身份、指纹和 offset 校验。
  新 epoch 继续 fence 旧 writer；不引入无限历史 epoch 可写兼容。
- 共享内存、待落盘数据和热回执有界。磁盘慢或读者阻塞时明确背压/拒绝，不静默丢弃。
- 检查点必须包含 producer/sequence 与零行 mutation 所需信息，不能仅保存最后一行 offset。

- [x] 仓库内 Python 接口、消费者、迁移示例与测试迁移；明确版本、批次和缺口语义。
- [x] 原生持久化任务接入 TableActor，按完整 mutation 前缀提交 manifest。
- [x] 持久化回执索引与 WAL 检查点，重启恢复不扫描已归档全部历史。
- [x] SHM/WAL 回收和后台任务生命周期接入真实 server 启停。
- [x] 小资源预算下跨多轮回收写入、精确重试、故障窗口恢复、旧快照读取验证。

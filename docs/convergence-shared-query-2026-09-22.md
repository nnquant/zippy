# 第二十五批：共享查询编译与原生派生表执行

日期：2026-09-22。推进 F14/F22/F29；原审计仍为 **25/34 已关闭、9 项开放**。
本批消除主包与独立客户端的查询编译分歧，没有宣布旧查询、Gateway 或控制面整体退出。

## 删除重复实现

主包删除独立 `_QueryExpr`、时间瞬时字面量类、`_NativeSqlCompiler`、SQL 字面量和表达式
渲染函数，改用 `zippy_client` 的表达式及唯一 SQL 编译器。`SqlSource` 明确传入表名、
命名空间、列序和计划操作；主包只提供原生表检查、逻辑分片和已有时间归一化结果，并为
尚存的 Rust 控制协议编码带类型标记的绑定。SQL 规则不再在该入口实现第二遍。

实际消除的行为分歧：

- 右连接、全连接使用两侧连接键的 `coalesce`，保留仅右侧存在的键。
- 替换已有列保持原列位置；新列追加到末尾。
- 重复投影列名统一拒绝；循环连接统一拒绝；分片按明确顺序形成 UNION ALL。
- 主包与客户端表达式可互用，时间瞬时字面量保留整数纳秒。
- `is_between` 生成两条显式比较，沿同一有界表达式执行路径运行。

主包与客户端的时间范围解析、表生命周期、Gateway residual、固定快照等仍有待收敛，
不以删除 SQL 编译器等同于 F14/F22 完成。

## 真实执行发现并修复的服务端缺口

原生矩阵首先复现了 `persisted SQL wildcard over a derived relation is unsupported`。
之前仅校验生成 SQL、由 fixture 返回结果的客户端测试不能证明 DataFusion 真正可执行。
服务端现在在规划前统计派生投影替换的保守展开量，并计入通配符引入的计算列；深层重复
投影超限仍在优化器运行前拒绝。LATERAL、列列表别名等未证明有界的形式继续拒绝。

物理输出预算补齐内置 `coalesce` 和单个定宽参数的 `to_timestamp_nanos`。函数通过实际
内置实现类型识别，不能仅靠同名函数绕过检查。COALESCE 的字符串值宽不超过输入值宽，
另计输出数组和选择掩码；未知函数及无法约束的变长转换仍拒绝。
规划预算格式由 11 升为 12，输出预算格式由 2 升为 3，避免混用旧估计。

## 资源预算仍有明确限制

新的嵌套连接验收曾在 1 GiB 配置下被正确拒绝：预留量为 2,513,600,484 字节。
这是保守规划/任务预留量，不是实测堆占用。验收脚本显式配置 4 GiB，并对同一查询用
1 GiB override 验证 `RESOURCE_EXHAUSTED`，随后验证足额预算下的结果。
**生产默认 512 MiB 没有改变**。复杂派生查询在默认预算下的可用范围仍是 F14 的后续问题，
不能把提高验收预算描述成资源估计已经优化。

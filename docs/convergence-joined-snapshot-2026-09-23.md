# F05 复核：联接查询的固定快照绑定

日期：2026-09-23。原审计仍为 33/34；F28 跨平台实机验收按用户要求延期。

复核发现，对普通 `left.join(right)` 的结果直接调用 `snapshot()`，客户端原先只捕获
左表；查询编译时却绑定两张表。加入第三张表的定向回归先稳定复现：捕获请求只有左表。
另一个边界是联接查询在捕获前克隆时，共享的右侧内部查询可能被后续快照覆盖，导致两个
查询用不同 snapshot ID 解析右侧 schema；捕获前缓存的 schema 也可能继续用于新快照。

现在 `Table.snapshot()` 遍历完整联接树，按出现顺序去重捕获全部来源，并在发起请求前
检查 32 个查询绑定上限。捕获后，所有内部查询都绑定同一 lease 并清除先前元数据缓存。
`Table._clone()` 为联接子树创建独立查询副本；`close()` 逐一关闭这些内部副本，最后
释放自身引用，使同一快照的派生查询关闭后可以确定性释放服务端 lease。

回归测试覆盖三表跨 namespace 捕获、捕获前克隆的双独立快照、旧 schema 缓存刷新、
重复来源去重和超出绑定上限时写入前拒绝。真实服务矩阵从空目录创建 append/frame/KV，
在手动联接捕获后写入、变更 schema、删除并同名重建，仍读取原边界且释放后不能再使用。

真实原生服务矩阵通过；独立客户端从当前源码构建 sdist/wheel 后在 Arrow 23.0.1
环境隔离安装并运行完整测试。本轮未执行 Windows/macOS 实机验收。

后续生命周期复核补齐关闭顺序：`Client.close()` 已撤销其读会话并清空固定快照连接后，
调用方仍持有的 `Table` 或 `FixedSnapshot` 可以继续幂等关闭。此前这一步会在已关闭的
Flight transport 上尝试再次发释放请求并抛出 `RuntimeError`。现在 `release_snapshot`
对已关闭 transport 返回 `False`，不再新建会话；关闭期间若会话撤销失败，原
`Client.close()` 仍报告该失败。公开 API 回归测试先复现异常，再确认两种句柄均可清理。

**225 passed**、覆盖率 **85.19%**。全仓 Black 92 文件、Ruff、mypy 91 文件，客户端
mypy 27 文件及 `git diff --check` 均通过。
